## A. Токен-слой

### A1. 🔴 Прозрачности в прод-токенах нет как класса

**Что:** alpha-примитивы записаны непрозрачными хексами, а полупрозрачные семантические
токены переуказаны на solid-аналоги.

**Доказательство** (`compliance-shared-components/src/lib/assets/styles/`):

```
$color-neutral-alpha-200: #fbfbff;        ← должно быть #fbfbff33 (20%)
$color-dark-neutral-alpha-300: #121b39;   ← должно быть #121b394d (30%)
$shadow-z-index-eleveation-2-color: #9e9e9e;  ← должно быть #9e9e9e26 (15%)
$cntnr-bg-transperent-default: $color-neutral-solid-125;  ← вместо alpha-500
$btn-bg-transperent-hover: $color-primary-100;            ← вместо alpha-0

grep -c "rgba|opacity"  все 4 файла     → 0 0 0 0
grep -cE '#[0-9a-fA-F]{8}'  все файлы   → 0
```

21 alpha-примитив × 2 бренда + 3 цвета тени × 2 бренда.

**Где кусало:** LIGA-9580 (фильтр ДН) — тень `Elevation 2` в Іт.2 вышла «надто важка»,
потому что взяли непрозрачный `#9e9e9e`; правили вручную в макете, не поняв, что это
дефект токен-слоя. Тот же дефект даст неверные оверлеи и `blanket-popup-background`.

**Что делать:** вернуть альфу в примитивы и цвета теней; проверить, было ли переуказание
`transperent`→solid осознанным решением (тогда нужен комментарий в файле) или следствием
экспорта. **Требует MR в `complianceclient`.**

### A2. 🟡 `highlight-bg` в Liga360 разошёлся с Figma

| | значение |
| --- | --- |
| прод `tokens-liga360.scss:84` | `#f9dd8b` (жёлтый) |
| Figma / Liga DS | `#e5e2ff` (= primary-200, фиолетовый) |
| United (оба источника) | `#b7d1ff` — сходятся |

Дополнительно: `#f9dd8b` — **хардкод-хекс, не привязанный ни к одному примитиву**
(`grep f9dd8b primitives-liga360.scss` → пусто), единственный такой в файле. Остальные
токены ссылаются на примитивы.

**Нужно решение:** жёлтая подсветка поиска в 360 — намеренная (тогда завести примитив и
обновить Figma) или наследие (тогда привести к primary-200).

### A3. 🟡 `text-warning` в United разошёлся на шаг шкалы

прод `#ff6c02` (`orange-red-600`) против Liga DS `#d65900` (`orange-red-700`).
Оба значения существуют в примитивах — то есть это выбор, а не опечатка. Нужно решить,
какой верен, и синхронизировать.

### A4. 🔴 `$status-*` есть в проде, но отсутствуют в дистрибутиве

`$status-positive` · `$status-negative` · `$status-warning` · `$status-blue` ·
`$status-passive` — именно они питают `compliance-status`. В `tokens.generated.css` их нет
(там другой набор — `--status-filled-*` / `--status-trasperent-*`). Из-за этого в макете
статусные пилюли собираются из примитивов вручную.

### A5. 🔴 Брейкпоинты и палитра дата-виза существуют только в дистрибутиве

74 токена есть в Liga DS и отсутствуют в прод-SCSS: 21 `colors-color-*` (дата-виз),
8 `monochrome-color-*`, 9 `screen-size-*` (брейкпоинты), 13 вариантов кнопок
(`btn-bg-danger-secondary-*`, `btn-bg-transperent-danger-*`), 9 `typo-*`, 2 бренд-цвета.
Следствие: респонсив в проде пишется числами, а не токенами.

## B. Компоненты — чего не хватает

### B1. 🔴 `compliance-status` без жёлтой / бурштиновой темы

Типы: `subtle · success · warning(orange-red) · danger · accent · info · debtor · notdebtor`.
Жёлтой нет. **Заблокировало** бейдж «PDF Структура власності» в LIGA-9432 — в MR !125
остался TODO, источник помечен не тем цветом.

### B2. 🟡 Канон node-цветов не определён

В токенах `--node-person: #015CE5` (синий) / `--node-company: #f4d20a` (жёлтый);
в Figma для тех же сущностей — plum/teal. Бэклог LIGA-9306. Цвет стоит на каждой карточке
сущности, поэтому расхождение видно постоянно. **Нужно решение дизайнера, какой канон.**

### B3. 🔴 Нет мульти-чип фильтра

В «Судах» (LIGA-9306) фильтр по нескольким токенам с логикой AND собран руками из
`compliance-input`. Паттерн повторяемый — кандидат в общий компонент.

### B4. 🔴 Нет токена контейнера-предупреждения

В макете «Судов» до сих пор висит `/* УТОЧНИТИ: точний токен контейнера-попередження
(orange-red-100) */` и временное `#fef4e8`. В проде подходящего семантического токена не
нашлось (есть `$cntnr-bg-other-success`, аналога для warning — нет).

### B5. 🔴 Нет своего tooltip

Нативный `title` не всплывает (в канвасе его перехватывает комент-шар), поэтому
используется оболочка Material `.mdc-tooltip__surface`. Собственного компонента в ДС нет.

### B6. 🟢 Иконочная кнопка — это отдельный компонент

`compliance-button` **требует** текстовый `btnName` и горизонтальные паддинги; иконочная
кнопка — `compliance-icon-button` (24/32/40/48, квадрат). Ловушка повторялась, пока не
попала в скилл `design-united-builder` v1.4.0. Оставлено как запись — документация закрыта,
кода это не касается.

### B7. 🔴 Шапка макси-виджета — не компонент

В развёрнутом макси заголовок виджета скрывается, а его роль играет
`.widget_maxi_navbar_container` — **глобальный класс в `styles.scss` приложения**, не
компонент ДС. Проверено на `compliance-company-sanctions-widget` (LIGA-9168).

### B8. 🔴 Кросс-брендовая протечка шрифта

Узлы mini-graph жёстко `font-family: Lato` — в United шрифт не подключён, отдаёт
системный sans вместо e-Ukraine. Кандидат-баг из LIGA-9432. Класс дефекта: бренд-значение
захардкожено в компоненте вместо токена.

### B9. 🔴 `ld-icon-button` не эмитит `ldClick` — выход объявлен, слушателя нет

**Что:** компонент объявляет `@Output() ldClick`, но в шаблоне у `<button>` нет
привязки клика и нет метода-обработчика. Событие не срабатывает никогда.

**Доказательство** (`projects/liga-ds/src/lib/button/icon-button.component.ts`):

```
template: `
  <button
    class="ld-button ld-button--icon-only"
    [class]="buttonClass"
    [type]="type"
    [disabled]="disabled || loading"      ← привязки клика НЕТ
    ...
`
@Output() ldClick = new EventEmitter<MouseEvent>();   ← есть, но никто не emit-ит
```

Для сравнения, соседний `button.component.ts` сделан правильно:
`(click)="onClick($event)"` в шаблоне и `this.ldClick.emit(event)` в `onClick`.

**Где кусало:** boss-interface (Іт.3, 28.08.2026) — крестик закрытия модалки «Звіт по
медіа» был собран по документации, через `(ldClick)`, и оказался мёртвым. Пин `2a12aefb`:
«Кнопка Клоуз не работает почему-то». Обошли нативным `(click)` — так уже вынужденно
сделано и в `subject-actions` того же макета (экспорт PDF, избранное). То есть workaround
разошёлся по коду раньше, чем нашли причину.

**Что делать:** добавить `(click)="onClick($event)"` и метод `onClick`, как в
`LdButtonComponent` (учесть `disabled`/`loading`). После этого убрать нативные `(click)`
в потребителях — иначе на исправленном компоненте получим двойное срабатывание.

### B10. 🔴 `ld-inline-inform`: host-стили написаны на несуществующий тег `ld-ii`

**Что:** селектор компонента — `ld-inline-inform`, а все host-правила записаны на
element-селектор `ld-ii`. Такого тега в DOM нет, поэтому **весь блок host-стилей мёртв**:
не применяются раскладка, отступы, скругление, шрифт и все четыре фона.

**Доказательство** (`projects/liga-ds/src/lib/inline-inform/inline-inform.component.ts`):

```
selector: 'ld-inline-inform',                                    ← тег в DOM
host: { '[class]': '"ld-ii ld-ii--" + type + " ld-ii--bg-" + background' },
styles: [`
  ld-ii { display:flex; gap:…; padding:…; border-radius:…; }     ← не матчится
  ld-ii.ld-ii--bg-warning { background: var(--color-other-colors-orange-red-100); }
  ld-ii.ld-ii--bg-grey / --bg-white / --bg-green { … }           ← не матчатся
`]
```

Проверено в браузере на собранном макете: элемент `<ld-inline-inform class="ld-ii
ld-ii--bg-warning ld-ii--full">`, `getComputedStyle(...).backgroundColor` →
`rgba(0, 0, 0, 0)`; `document.querySelectorAll('ld-ii').length` → `0`.

Дочерние правила (`.ld-ii__icon`, `.ld-ii__body`, `.ld-ii__desc`, …) — классовые, они
работают. Поэтому дефект выглядит как «просто нет фона», а не как сломанный компонент.

**Где кусало:** boss-interface — виджет «Структура власності» весь этот срок показывал
блок `background="warning"` без подложки, и никто не связал это с ДС. В Іт.3 то же самое
всплыло в модалке «Звіт по медіа»: пришлось локально дублировать фон тем же токеном,
на который ссылается мёртвое правило ДС.

**Что делать:** заменить element-селектор на `:host` (класс уже вешается на host) либо на
классовый `.ld-ii`. Правка на один селектор, но затрагивает все потребители — после неё
проверить, где фон уже продублирован локально, и убрать дубли.

## C. Иконки

### C1. 🔴 928 файлов вместо 464 — цвет запечён в SVG

442 из 464 файлов различаются между `assets/icons/united/` и `assets/icons/liga360/`.
Причина различия — **цвет внутри SVG**:

```
united/*.svg   : 731 × fill="#303438"   (n-900 united)
liga360/*.svg  : 608 × fill="#25252A"   (n-900 liga360)
```

Плюс united-версии части глифов тащат лишние `mask` / `clip-path` (`AI.svg`: united — маска,
liga360 — один `path`).

С `fill="currentColor"` нужен **один** набор, а цвет задаётся токеном на месте
использования. Это же убирает необходимость чинить иконку дважды.

### C2. 🔴 В дистрибутиве иконки только React и только один бренд

`icons/` — 459 SVG + React/SVGR-компоненты (`@liga360/icons`), из `@neodisa/liga-ds` для
Angular не экспортируются. Набор беднее прода (459 против 464) и однобрендовый.
Источником должен стать прод-набор, а не этот.
